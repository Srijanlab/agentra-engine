- Engine = state authority, loop = execution — a hard split. Trigger endpoints only `registry.enqueue_job({cycle|promote|prod_debug|human_resume})`; agentra-loop drains the queue and reports back. The engine carries no `claude-agent-sdk` and no docker/deploy code.
- One RPC contract. `POST /internal/rpc` gated by `AGENTRA_INTERNAL_TOKEN` (+ optional Vercel-header IP allowlist), restricted to the `_REGISTRY_METHODS` / `_MEMORY_METHODS` frozensets, is the entire state surface the loop may touch. Credential-holding side doors are separate token-gated endpoints (`/internal/git-token`, `/internal/slack/message`, `/internal/runs/{id}/log`).
- Dual-path persistence. Every registry/memory write is `if core._ddb: <DynamoDB> else: <local JSON under AGENTRA_HOME>`. DynamoDB (static prefixed `AGENTRA_AWS_*` IAM keys) backs prod; local JSON serves the CLI, tests, and the loop's own process. `cloud_mode()` gates all checkout-dependent behavior.
- Per-job lease: each claimed job is reclaimed (or poison-failed after `AGENTRA_JOB_MAX_ATTEMPTS`) based on its own `heartbeat_at`, renewed by the loop via `/internal/jobs/{id}/heartbeat`; `release_job` gives a CAS-guarded fast release on graceful shutdown.
- Unified 401 shape (issue #83): the Firebase gate, the verify-token gate, and the `/trigger/queue` gate (via `QueueAuthError` + an app-level exception handler) all return `{detail, error: "authentication_required", hint}` from `verify_token.unauthenticated_body()`; the queue gate overrides only the static hint. Hints never leak secret values.
- Tightened dashboard auth: Firebase tokens must carry `email_verified=true` (403 otherwise), and the `?access_token=` query fallback is limited to the SSE `GET /runs/{id}/logs` path.
- Pub/Sub push auth is fail-closed: OIDC is accepted only when both audience and service-account email are configured and the verified email claim matches.
- Durable signals feed: `GET /signals` is backed by `registry/signals.py` (dual-path: single DynamoDB `system` item `key="signals"` or local `signals.json`), a bounded ring of the newest 200 events. DynamoDB appends are an atomic `list_append` followed by a size-conditioned trim (bounded retries). `server.utils._server_log` writes to it alongside the logger and swallows storage errors, replacing a `server.log` file reader that nothing ever wrote to.
- Human answers converge on `dispatch_human_answer` regardless of channel (dashboard, Slack, GitHub comment): first answer enqueues `human_resume`, duplicates are no-op acks, and the resolution is echoed to the Slack thread.
