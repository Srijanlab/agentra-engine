- Engine = state authority, loop = execution: trigger endpoints only `registry.enqueue_job(...)`; the loop drains the queue and reports back through the whitelisted `POST /internal/rpc`. No `claude-agent-sdk`, no deploy code here.
- Dual-path persistence everywhere (`if core._ddb: DynamoDB else local JSON under AGENTRA_HOME`); `cloud_mode()` gates checkout-dependent behavior.
- Durable queue with self-healing: CAS claim on a `by-status` GSI, per-job heartbeat staleness requeue (poison-fail after max attempts), native DynamoDB TTL on terminal jobs.
- Correctness reads are window-independent (new): per-app partition queries with server-side filters and `limit=None` for `list_app_runs`/`list_jobs`, never-truncated `list_loops_by_status`, and `reconcile_stale_runs` unioning a global window with every in-flight run per registered app, so one busy app can't hide another's runs/jobs/loops from the scheduler or reconcilers. Regressions live in `tests/test_{run,loop,schedule}_window*.py`.
- Operator audit trail (new): `server/audit.py` (`actor_for`/`audit_log`) resolves the caller (Firebase email, `verify-token`, `loop` for `/internal/*`, else `anonymous`) and threads it as `actor` through `_server_log` -> `registry.record_signal`, so the `GET /signals` feed shows who paused/resumed, registered/updated apps, triggered runs, or answered a human gate.
- Shared app-config write path (new): `routes/app_config.py::_apply_app_config` applies objective + `EnvironmentConfig` fields and commits `.agentra/` (skipped in cloud mode), reused by register and update so `apps.py` stays under the 500-line cap.
- Signals feed: bounded ring of the newest 200 events (single DynamoDB `system` item via atomic `list_append` + conditional trim, or local `signals.json`); `_server_log` never raises on persist failure.
- Unified 401 shape via `verify_token.unauthenticated_body()` across the Firebase, verify-token and `/trigger/queue` gates; the queue gate raises `QueueAuthError` handled by an app-level handler.
- Module-proxy pattern for `registry`/`memory`; memory modelled as GitHub Issues/Projects via 5 mixins with regex failure triage; SRP + 500-line cap + domain subfolders per CLAUDE.md; checkout/Claude-dependent features return 503.
