- Storage is dual-path everywhere: every registry/memory write and read branches on `core._ddb is not None` between a DynamoDB call and a local-JSON fallback, so the same code runs in prod, dev, and tests.
- The job queue models a lease, not just a status: `claimed` jobs carry `claimed_at`/`heartbeat_at`, and `touch_job` (surfaced to the loop via `POST /internal/jobs/{id}/heartbeat`) lets a long-running cycle keep renewing its lease instead of relying on a single fixed timeout — but the staleness check is computed per-app (max heartbeat across that app's claimed jobs), not per-job, trading a possible false-negative for simplicity.
- Scheduling cadence is unified behind one pure function (`compute_schedule_status`) that now branches on `schedule_continuous` internally rather than exposing two different call paths — the cron-tick enqueue and the read-only `/schedule` endpoint always agree.
- Auth is composed from small single-purpose gates (`verify_token.py`, `queue_auth.py`, `env.py`, `auth.py`) each owning one credential scheme, checked in a fixed order in `auth_middleware`, rather than one large gate function branching on route.
- Pre-prod/beta isolation is env-var-name-swapping (`AGENTRA_PREFLIGHT_DEMO` -> `BETA_*` names) rather than a separate config file or deployment-specific code path, keeping one codebase for prod and beta.
- Request/response pydantic models are kept out of route-handler files once a file nears the line-count limit (`app_payloads.py` split from `apps.py`), following the repo's CLAUDE.md SRP/file-size rule literally rather than as a suggestion.
