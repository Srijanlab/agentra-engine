- **Orchestrator comment allowlist** – Every comment the orchestrator posts (escalation markers, answers) must have its prefix in `_INTERNAL_COMMENT_PREFIXES` so the system never mis‑identifies orchestrator text as a human reply.
- **Live GitHub label handling** – Reading label membership uses the helper `_label_names()` to transform the REST label objects (`{name: …}`) into plain strings; the fake connector still uses strings, keeping the logic correct across test and production.
- **Loop recency ordering** – The visible loop list is sorted by `_recency()` (last real run time, or creation time if no run finished). Administrative changes that only touch the `updated_at` field no longer move loops up.
- **Feature sub‑issue gating** – The new `open_sub_issue_count()` helper queries GitHub for how many filed sub‑issues remain open. Build completion and shipping steps check this count before marking a parent issue code‑complete or shipped, preventing premature promotion of multi‑part features.
- **Three‑layer cache for GitHub** – `gh_cache` now uses an in‑process dict + durable storage (DynamoDB or local JSON) with TTL logic. Producers can return a `FetchResult` containing an etag; the cache maps from key to value, timestamp, expiry, and optionally etag, serving stale data on transient errors.
