- Engine = state authority, loop = execution: trigger endpoints only enqueue jobs (`cycle|promote|prod_debug|human_resume`); agentra-loop drains the queue and reports back over the token-gated `POST /internal/rpc` whitelist. No `claude-agent-sdk` or deploy code here.
- Dual-path persistence: every registry/memory write is `if core._ddb: <DynamoDB> else: <local JSON under AGENTRA_HOME>`; `cloud_mode()` gates checkout-dependent behavior.
- Durable queue with self-healing: CAS claim on a `by-status` GSI, per-job heartbeat staleness requeue (poison-fail after max attempts), native DynamoDB TTL on terminal jobs.
- Unfiltered-history reconciliation: status-based loop/run lookups (`list_loops_by_status`, `list_app_runs(limit=None)`) paginate the whole per-app GSI partition with server-side filters, and `reconcile_stale_runs` unions the newest global window with every queued/running run per app, so old stuck work can't fall out of a fixed-size window. Capped `list_loops`/`list_runs` stay display-only.
- Operator audit trail: `server/audit.py` (`actor_for`/`audit_log`) resolves the caller (Firebase email -> `verify-token` -> `loop` for `/internal` -> `anonymous`) and threads it into `_server_log(..., actor=)` / `registry.record_signal(..., actor=)`, so the durable signals feed records who paused, re-pointed the LLM backend, registered/updated/removed an app, triggered, or answered a human gate. `list_signals` always emits an `actor` key.
- App-config apply/persist is factored into `server/routes/app_config.py::_apply_app_config` (objective + `EnvironmentConfig` fields, `.agentra/` commit off cloud mode) and shared by register and update, keeping `apps.py` under the file cap.
- Signals store hardening: `record_signal` on DynamoDB is an atomic `list_append` plus a size-conditioned trim with bounded retries, replacing a read-modify-write; `_server_log` never raises on persist failure.
- Unified 401 shape: Firebase, verify-token and `/trigger/queue` gates all return `{detail, error: "authentication_required", hint}` via `verify_token.unauthenticated_body()`; the queue gate raises `QueueAuthError` handled at app level. The Firebase gate also requires `email_verified`.
- Module-proxy pattern for `registry`/`memory`; Memory modelled as GitHub Issues/Projects composed from 5 mixins.
- SRP + 500-line file cap + domain subfolders enforced by CLAUDE.md; features needing a checkout return 503 rather than half-working.
