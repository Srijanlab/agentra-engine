- Engine = state authority, loop = execution. Trigger endpoints only `registry.enqueue_job(...)`; agentra-loop drains the queue and reports back through the token-gated `/internal` RPC. No `claude-agent-sdk`, no deploy code here.
- Dual-path persistence: every registry/memory write is `if core._ddb: <DynamoDB> else: <local JSON>`.
- Durable signals feed: `GET /signals` is backed by `registry/signals.py` (single DynamoDB `system` item `key="signals"` or local `signals.json`), a bounded ring of the newest 200 events. DynamoDB writes use an atomic `list_append` then a conditional size-checked trim with bounded retries (no read-modify-write). `server.utils._server_log` logs and persists, swallowing persistence errors.
- Per-job heartbeat leases: `_requeue_stale_claims` judges each claimed job by its own `heartbeat_at`; the loop keeps a lease alive via `/internal/jobs/{id}/heartbeat`; jobs that exhaust attempts are poison-failed and raise a human gate.
- Tightened auth: the Firebase gate requires `email_verified`; `?access_token=` is accepted only on the SSE `GET /runs/{id}/logs` path; `/trigger/queue` Pub/Sub OIDC requires audience AND a verified service-account email match, and failures raise `QueueAuthError` rendered by an app-level exception handler as the shared 401 shape with a queue-specific static hint.
- Single human-answer path: `dispatch_human_answer` serves the dashboard, GitHub-comment poll and Slack; it is idempotent once answered, echoes to the Slack thread, and marks the queued run failed if job enqueue fails.
- Unified 401 shape (issue #83): `{detail, error: "authentication_required", hint}` built by `verify_token.unauthenticated_body()`, never leaking secret values.
