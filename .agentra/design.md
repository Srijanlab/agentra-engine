- Engine = state authority, loop = execution — a hard split. Trigger endpoints only `registry.enqueue_job(...)`; agentra-loop drains the queue and reports back over the single `POST /internal/rpc` contract (whitelisted `_REGISTRY_METHODS` / `_MEMORY_METHODS`), with credential-holding side doors as separate token-gated endpoints.
- Dual-path persistence: every registry/memory write is `if core._ddb: <DynamoDB> else: <local JSON under AGENTRA_HOME>`; `cloud_mode()` gates checkout-dependent behavior.
- Per-job heartbeat leases: `_requeue_stale_claims` evaluates each claimed job on its own `heartbeat_at` (replacing an earlier per-app max-heartbeat ceiling), so one live job can no longer mask another stale job for the same app; exhausted jobs are poison-failed and raise a human gate.
- Durable signals feed: `GET /signals` is backed by `registry/signals.py` (single DynamoDB `system` item `key="signals"` or local `signals.json`), a bounded ring of the newest 200 events. DynamoDB appends use an atomic `list_append` plus a size-conditioned trim with bounded retries instead of read-modify-write; `server.utils._server_log` writes to it alongside the logger and swallows persistence errors.
- Unified 401 shape (issue #83): the Firebase gate, verify-token gate and `/trigger/queue` gate all build their body from `verify_token.unauthenticated_body()`; `/trigger/queue` raises `QueueAuthError` (handled by a registered exception handler) and swaps in a static, config-independent hint.
- Hardened auth: Firebase gate requires `email_verified is True` (403 `email_not_verified`) and only accepts `?access_token=` on `GET /runs/{id}/logs`; Pub/Sub OIDC on `/trigger/queue` requires both audience and a matching verified service-account email.
- Human answers are idempotent across channels (dashboard / Slack / GitHub comment): once `need_human` is cleared, further answers only ack the Slack thread.
