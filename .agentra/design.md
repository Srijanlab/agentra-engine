- Dual-storage pattern everywhere in `registry/`: every function branches on `core._ddb is not None` (DynamoDB) vs local JSON, so the same code path runs in prod, CLI, and tests.
- Job queue as the only cycle-triggering mechanism: HTTP trigger endpoints never run work themselves, only `registry.enqueue_job(...)`; the loop polls/claims. Lease-based job ownership (claim + heartbeat + stale-reclaim + attempt cap + poison-job human gate) mirrors a lightweight SQS-visibility-timeout pattern, hand-rolled over DynamoDB CAS writes (`_conditional_write`).
- Scheduling cadence is unified behind one pure function (`compute_schedule_status`) consumed by both the cron tick and the read-only schedule endpoint, with continuous mode expressed as a variant of the same status object rather than a separate code path.
- Two-tier LLM backend config: a single global transport toggle (`llm_backend`) vs. a per-app, per-SDLC-agent-id backend map (`llm_backends`), with the legacy single field folded onto the `implementation` agent id for backward compatibility.
- Auth is layered: outer CORS middleware, then a single `auth_middleware` that tries a scoped read-only verify-token bypass first, then falls through to the Firebase gate; separate per-route bearer/Basic/OIDC checks (`queue_auth.py`, `_require_token` in `internal.py`, `_verify_tick_auth` in `triggers.py`, `_verify_alarm_webhook_auth`) guard machine-to-machine endpoints independently of the user-facing gate.
- RPC surface is an explicit method whitelist (`_REGISTRY_METHODS`/`_MEMORY_METHODS`) rather than exposing full objects, with a further subset (`_MEMORY_MUTATION_METHODS`) marked for cache invalidation — an allowlist-first design that fails closed (403) for anything not enumerated.
- Config request/response shapes are centralized as Pydantic models in one file (`app_payloads.py`) shared by register/update routes, keeping the route handlers themselves thin.
- Best-effort/never-fail wrappers around anything that touches an external system on a hot path (`_app_digest` catches per-app failures so one bad app doesn't 500 the list; `gh_cache` serves stale data on producer error; `/health` catches everything).
