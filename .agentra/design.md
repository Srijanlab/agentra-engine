- Dual-path storage everywhere in `registry`/`memory`: every write/read function is `if core._ddb is not None: <DynamoDB call> else: <local JSON file>` — no ORM, no ABC, just an inline branch per function, so tests/CLI/local dev exercise the same code path as prod minus the backend.
- The engine is a pure state/credential broker: cycles never run here. Every mutating trigger route follows the same shape — pause check, dedup on a `dedup_key`, `registry.enqueue_job(...)`, return `{triggered, run_key, job_id, queued}` — and the loop (a separate service) claims and executes.
- A single token-gated RPC surface (`POST /internal/rpc`) fronts two frozenset method whitelists (`_REGISTRY_METHODS`, `_MEMORY_METHODS`) instead of exposing `registry`/`Memory` as a general-purpose API — adding a capability for the loop means adding a name to a whitelist, not a new route.
- Job leasing uses heartbeat renewal (`touch_job`/`POST /internal/jobs/{id}/heartbeat`) plus a per-app (not per-job) stale-reclaim window, so a crashed loop can't strand work but one live job of an app's heartbeat protects that app's whole claimed set from over-eager reclaim.
- Per-app LLM backend selection is modeled as a map keyed by SDLC agent id (`VALID_SDLC_AGENT_IDS`) rather than one flag per app, with the old single `llm_backend` field folded in as the `implementation` agent's override for back-compat.
- Continuous scheduling (`schedule_continuous`) is layered onto the existing cadence-based `ScheduleStatus` rather than a separate code path — `compute_schedule_status` branches internally, and callers (`/trigger/scheduled`, `GET /apps/{app}/schedule`) are unchanged.
- Auth is layered: Firebase ID-token gate (dashboard users) -> scoped read-only verify-token bypass for pre-prod black-box checks (`verify_token.py`, production-disabled) -> per-route bearer/Basic/OIDC checks for machine callers (`/internal/*`, `/trigger/*`). Each layer is a separate small module rather than one large auth file.
- Request/response Pydantic models for app config are pulled into their own module (`routes/app_payloads.py`) as the route file grew, following the repo's enforced 500-line-per-file / SRP convention (CLAUDE.md).
