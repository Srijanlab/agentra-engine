- Two-plane split enforced at the code level: the engine (this repo) never runs SDLC/cycle logic — every trigger records a run + `registry.enqueue_job(...)` and returns; agentra-loop claims/executes, calling back only through the whitelisted `/internal/rpc`, `/internal/git-token`, `/internal/slack/message` (credentials never leave the engine).
- Every registry collection is dual-path: DynamoDB when `AGENTRA_DYNAMODB_TABLE_PREFIX` is set (the deployed engine), local JSON under `AGENTRA_HOME` otherwise (CLI/tests/dev) — same function, branch on `core._ddb`.
- Job queue is a CAS state machine (`pending -> claimed -> done|failed`) with a heartbeat-renewable lease: `touch_job` renews it and piggybacks the run's own staleness clock (`updated_at`), so a long cycle must heartbeat both its job and its run or both get reclaimed on the same threshold (`AGENTRA_STALE_HEARTBEAT_SECONDS`). Exhausting `max_job_attempts` converts a repeatedly-dying job into a human-gated failure instead of an infinite requeue loop.
- Auth is layered per-route rather than one global gate: Firebase sign-in (dashboard), a scoped read-only verify token (pre-prod black-box checks, path+method restricted, prod-disabled), a dedicated tick token (cron), Basic auth (alarm webhook), and internal-bearer-or-Pub/Sub-OIDC (`/trigger/queue`) — each independently swappable and each fails closed once any credential for it is configured.
- Scheduling cadence is centralized in `registry.scheduler.compute_schedule_status`, which now branches on a per-app `schedule_continuous` flag: fixed cadence derives due-time from `last_run_at + cadence_hours`, continuous mode derives it from a fixed gap after the last cycle-run activity/in-flight state — one function, one source of truth for both the cron enqueue path and the dashboard's read endpoint.
- LLM backend selection is per-app AND per-SDLC-agent (a map keyed by agent id, e.g. `implementation`, `testing`, `deployment`), not a single global/app toggle, with legacy single-value config folded onto the `implementation` agent for back-compat.
- Preflight/beta isolation (`AGENTRA_PREFLIGHT_DEMO`) swaps the DynamoDB table prefix and internal token via a tiny indirection layer (`server/env.py`) rather than duplicating every call site's env lookup.
