- Dual-storage convention: every registry/memory write branches on `core._ddb is not None`, giving local-JSON dev/test parity with the DynamoDB prod path with no separate test doubles.
- Job/run staleness is now a single, app-scoped heartbeat mechanism (`core.stale_heartbeat_seconds()`, `registry.touch_job`, `POST /internal/jobs/{id}/heartbeat`) shared by the job-claim reaper and the run/loop reconciler, replacing the earlier flat 1h timer — a long cycle survives by heartbeating rather than by raising a fixed timeout.
- Auth is decomposed into three narrow, independently testable modules (`auth.py`, `verify_token.py`, `queue_auth.py`) each owning one credential scheme, composed in `auth_middleware`/route dependencies rather than one large gate.
- Scheduling is unified behind `registry.scheduler.compute_schedule_status`, now branching internally between fixed-cadence and continuous (`schedule_continuous`) apps so both the cron enqueue path and the read-only schedule endpoint stay in lock-step.
- Pre-prod isolation is enforced in code, not just convention: `verify_token.py` hard-refuses its own header in production via `VERCEL_ENV`/`AGENTRA_ENVIRONMENT`, so a pre-prod-only credential can't be reused if accidentally set on prod.
- Backward-compatible credential rollout pattern (`_verify_tick_auth`): a new dedicated secret is layered in as the preferred path while the old shared secret keeps working until the new one is actually provisioned, avoiding a flag-day cutover for `/trigger/cron`.
