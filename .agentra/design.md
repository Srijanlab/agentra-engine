- Durable signals feed: `GET /signals` is backed by `registry/signals.py` (dual-path: single DynamoDB `system` item `key="signals"` or local `signals.json`), a bounded ring of the newest 200 events. DynamoDB appends are atomic (`list_append` via `update_item`) with a size-conditioned trim retried up to 5 times, replacing the earlier get-then-put read-modify-write. `server.utils._server_log` writes to it alongside the logger and swallows persistence errors, so logging never breaks a request.
- Per-job lease staleness: `_requeue_stale_claims` evaluates each claimed job on its own `heartbeat_at`/`claimed_at` (no per-app MAX heartbeat ceiling); stale jobs are re-queued or poison-failed once `max_job_attempts` is reached.
- Tightened auth: the Firebase gate requires `email_verified` (403 `email_not_verified`) and accepts `?access_token=` only on `GET /runs/{id}/logs` (SSE). `/trigger/queue` raises `QueueAuthError`, rendered by an app-level exception handler as the shared 401 body with a static hint; the Pub/Sub OIDC path requires both `AGENTRA_PUBSUB_AUDIENCE` and `AGENTRA_PUBSUB_SERVICE_ACCOUNT_EMAIL` (fail closed), with a startup warning when only the audience is set.
- Human-answer dispatch ordering: `dispatch_human_answer` enqueues the `human_resume` job before recording the answer, marks the queued run failed on enqueue error, and the route returns 503 telling the user the answer was not recorded so it can be resubmitted.
