- Engine = state authority, loop = execution — a hard split. Trigger endpoints only `registry.enqueue_job({cycle|promote|prod_debug|human_resume})`; agentra-loop drains the queue and reports back. The engine carries no `claude-agent-sdk` and no docker/deploy code.
- One RPC contract. `POST /internal/rpc` gated by `AGENTRA_INTERNAL_TOKEN` (+ optional Vercel-header IP allowlist), restricted to the `_REGISTRY_METHODS` / `_MEMORY_METHODS` frozensets, is the entire state surface the loop may touch. Credential-holding side doors are separate token-gated endpoints (`/internal/git-token`, `/internal/slack/message`, `/internal/runs/{id}/log`).
- Dual-path persistence. Every registry/memory write is `if core._ddb: <DynamoDB> else: <local JSON under AGENTRA_HOME>`. `cloud_mode()` gates all checkout-dependent behavior.
- Per-job heartbeat leases: each claimed job is reclaimed or poison-failed on its own `heartbeat_at` (no longer an app-wide max), renewed by `POST /internal/jobs/{job_id}/heartbeat`.
- Durable signals feed: `GET /signals` is backed by `registry/signals.py` (dual-path: single DynamoDB `system` item `key="signals"` or local `signals.json`), a bounded ring of the newest 200 events. DynamoDB appends are atomic (`list_append`) with a size-conditioned trim retried up to 5 times; `server.utils._server_log` writes to it alongside the logger and swallows persist errors.
- Unified 401 shape (issue #83): the Firebase gate, the verify-token gate and the `/trigger/queue` gate all return `{detail, error: "authentication_required", hint}` via `verify_token.unauthenticated_body()`; the queue gate swaps in a static hint and signals failure with `QueueAuthError` + an app-level exception handler.
- Hardened auth: Firebase tokens need `email_verified`; `?access_token=` is accepted only for the SSE `GET /runs/{id}/logs`; Pub/Sub OIDC on `/trigger/queue` requires an audience AND a verified matching service-account email.
- Human-answer dispatch (`routes/human_input.py`): a second answer after the first is a no-op ack; resume is enqueued as a `human_resume` job deduped on `human_resume:{app}:{issue}`, and a failed enqueue marks the run failed and re-raises (route returns 503 with the answer not recorded).
- Other patterns unchanged: multi-part feature guard (#38), shared `_escalate_blocking_failure` for auth/unfixable failures (#42/#46/#47), gh_cache stale-on-error reads, legacy `status:shipped` back-compat reads.
