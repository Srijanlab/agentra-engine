- Engine = state authority, loop = execution: trigger endpoints only `registry.enqueue_job(...)`; agentra-loop drains the queue. No `claude-agent-sdk`, no deploy code here.
- Single RPC contract: `POST /internal/rpc` (bearer `AGENTRA_INTERNAL_TOKEN`, optional Vercel-header IP allowlist) restricted to `_REGISTRY_METHODS` / `_MEMORY_METHODS`; credential-holding side doors are separate token-gated endpoints.
- Dual-path persistence: `if core._ddb: <DynamoDB> else: <local JSON under AGENTRA_HOME>`; `cloud_mode()` gates checkout-dependent behaviour.
- Job leases are per job: each claimed job is judged by its own `heartbeat_at` (renewed via `/internal/jobs/{id}/heartbeat` -> `touch_job`); stale claims are re-queued or poison-failed after `AGENTRA_JOB_MAX_ATTEMPTS`, raising a human gate. Replaces the earlier per-app MAX-heartbeat ceiling.
- Durable signals feed: `GET /signals` is backed by `registry/signals.py` (single DynamoDB `system` item `key="signals"` or local `signals.json`), a ring of the newest 200 events. DynamoDB appends are atomic (`list_append` `update_item`) with a size-conditioned trim retried up to 5 times, so concurrent writers don't overwrite each other. `server.utils._server_log` logs and persists a signal, swallowing storage errors with a warning.
- Unified 401 contract (issue #83): Firebase, verify-token and `/trigger/queue` gates all build the `{detail, error: "authentication_required", hint}` body from `verify_token.unauthenticated_body()`; the queue gate overrides only `hint` (static, config-independent) and signals failure by raising `QueueAuthError`, rendered by an exception handler registered in `server/__init__.py`.
- Hardened auth: Firebase gate requires `email_verified is True` (403 `email_not_verified`); `?access_token=` is accepted only for `GET /runs/{id}/logs` (SSE); Pub/Sub OIDC on `/trigger/queue` requires `AGENTRA_PUBSUB_SERVICE_ACCOUNT_EMAIL` whenever `AGENTRA_PUBSUB_AUDIENCE` is set (fail-closed, startup warning).
- Human-input answers are idempotent across channels: `dispatch_human_answer` no-ops (`already_answered`) once the `need_human` label is gone, and every answer is echoed back to the Slack thread.
- Other patterns unchanged: verify-token read-only bypass (403 in production), `gh_cache` stale-on-error read-through, `pipeline_stages()` and `compute_schedule_status` as single sources of truth, `_escalate_blocking_failure` for all blocking-failure escalations.
