- Engine = state authority, loop = execution — a hard split. Trigger endpoints only `registry.enqueue_job({cycle|promote|prod_debug|human_resume})`; agentra-loop drains the queue and reports back. The engine carries no `claude-agent-sdk` and no docker/deploy code.
- One RPC contract. `POST /internal/rpc` gated by `AGENTRA_INTERNAL_TOKEN` (+ optional Vercel-header IP allowlist), restricted to the `_REGISTRY_METHODS` / `_MEMORY_METHODS` frozensets, is the entire state surface the loop may touch. Credential-holding side doors are separate token-gated endpoints (`/internal/git-token`, `/internal/slack/message`, `/internal/runs/{id}/log`).
- Dual-path persistence. Every registry/memory write is `if core._ddb: <DynamoDB> else: <local JSON under AGENTRA_HOME>`. DynamoDB (static prefixed `AGENTRA_AWS_*` IAM keys) backs prod; local JSON serves the CLI, tests, and the loop's own process. `cloud_mode()` gates all checkout-dependent behavior.
- Per-job heartbeat lease: each claimed job is judged stale on its own `heartbeat_at` (fallback `claimed_at`); stale jobs are re-queued or, past `AGENTRA_JOB_MAX_ATTEMPTS`, poison-failed into a human gate.
- Unified 401 shape (issue #83): the Firebase gate (`auth.py`), verify-token gate (`verify_token.py`) and `/trigger/queue` gate (`queue_auth.py`, via a `QueueAuthError` exception handler) all return `{detail, error: "authentication_required", hint}` built from `verify_token.unauthenticated_body()`; hints never leak secret values, and the queue hint is a static string.
- Auth hardening: the Firebase gate requires `email_verified` (403 otherwise) and accepts the `?access_token=` query token only on the SSE `GET /runs/{id}/logs` path; Pub/Sub OIDC on `/trigger/queue` requires both audience and service-account email configured, fail-closed otherwise, with a startup warning for the half-configured case.
- Human answers are recorded only after the resume job is enqueued (enqueue failure -> failed run + 503, answer not persisted); duplicate answers from another channel are a no-op ack that also reflects resolution into the Slack thread.
- Durable signals feed: `GET /signals` is backed by `registry/signals.py` (dual-path: single DynamoDB `system` item `key="signals"` or local `signals.json`), a bounded ring of the newest 200 events. DynamoDB appends are atomic `list_append` updates followed by a size-conditioned trim with bounded retries. `server.utils._server_log` writes to it alongside the logger and swallows storage errors, replacing a `server.log` file reader that nothing ever wrote to (and that couldn't persist on serverless hosts).
