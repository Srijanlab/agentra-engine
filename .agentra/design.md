- Engine = state authority, loop = execution — a hard split. Trigger endpoints only `registry.enqueue_job({cycle|promote|prod_debug|human_resume})`; agentra-loop drains the queue and reports back. The engine carries no `claude-agent-sdk` and no docker/deploy code.
- One RPC contract. `POST /internal/rpc` gated by `AGENTRA_INTERNAL_TOKEN` (+ optional Vercel-header IP allowlist), restricted to the `_REGISTRY_METHODS` / `_MEMORY_METHODS` frozensets, is the entire state surface the loop may touch. Credential-holding side doors are separate token-gated endpoints (`/internal/git-token`, `/internal/slack/message`, `/internal/runs/{id}/log`).
- Dual-path persistence. Every registry/memory write is `if core._ddb: <DynamoDB> else: <local JSON under AGENTRA_HOME>`. `cloud_mode()` gates all checkout-dependent behavior.
- Job leases are per-job: each claimed job is judged by its own `heartbeat_at`; stale ones are re-queued or poison-failed after `AGENTRA_JOB_MAX_ATTEMPTS` (reverted from the earlier per-app max-heartbeat ceiling).
- Durable signals feed: `GET /signals` is backed by `registry/signals.py` (single DynamoDB `system` item `key="signals"` or local `signals.json`), a bounded ring of the newest 200 events. DynamoDB appends are atomic `list_append` with a conditional, size-checked trim (bounded retries). `server.utils._server_log` writes to it alongside the logger and swallows persistence errors.
- Hardened auth: the Firebase gate requires `email_verified`, and `?access_token=` is honored only on the SSE `GET /runs/{id}/logs`. `/trigger/queue` uses `QueueAuthError` + a registered exception handler for a uniform 401 body with a static, config-independent hint; Pub/Sub OIDC requires `AGENTRA_PUBSUB_SERVICE_ACCOUNT_EMAIL` whenever an audience is set (fail-closed). Unified 401 shape (issue #83) comes from `verify_token.unauthenticated_body()`.
- Human answers are idempotent across channels (dashboard/Slack/GitHub comment): the first enqueues `human_resume`; later ones only ack.
- Multi-part feature guard (#38): the parent issue is only marked code-complete when `open_sub_issue_count` is 0.
- Failure escalation (#42/#46/#47): auth and unfixable failures share `_escalate_blocking_failure`, deduped against similar open bugs.
