- Engine = state authority, loop = execution — a hard split. Trigger endpoints only `registry.enqueue_job({cycle|promote|prod_debug|human_resume})`; agentra-loop drains the queue and reports back. The engine carries no `claude-agent-sdk` and no docker/deploy code.
- One RPC contract. `POST /internal/rpc` gated by `AGENTRA_INTERNAL_TOKEN` (+ optional Vercel-header IP allowlist), restricted to the `_REGISTRY_METHODS` / `_MEMORY_METHODS` frozensets, is the entire state surface the loop may touch. Credential-holding side doors are separate token-gated endpoints (`/internal/git-token`, `/internal/slack/message`, `/internal/runs/{id}/log`).
- Dual-path persistence. Every registry/memory write is `if core._ddb: <DynamoDB> else: <local JSON under AGENTRA_HOME>`. DynamoDB (static prefixed `AGENTRA_AWS_*` IAM keys) backs prod; local JSON serves the CLI, tests, and the loop's own process. `cloud_mode()` gates all checkout-dependent behavior.
- Job leases are per-job: each claimed job is reclaimed (or poison-failed after `AGENTRA_JOB_MAX_ATTEMPTS`) based on its own `heartbeat_at`, renewed by the loop via `/internal/jobs/{id}/heartbeat`.
- Unified 401 shape (issue #83): the Firebase gate (`auth.py`), verify-token gate (`verify_token.py`) and `/trigger/queue` gate (`queue_auth.py`, via a `QueueAuthError` exception handler) all return `{detail, error: "authentication_required", hint}` from `verify_token.unauthenticated_body()`; the queue gate substitutes a static hint. Hints never leak secret values.
- Auth hardening: `?access_token=` is honored only for the SSE `GET /runs/{id}/logs` path; Firebase tokens must have `email_verified`; Pub/Sub OIDC requires an explicit service-account email whenever an audience is configured.
- Durable signals feed: `GET /signals` is backed by `registry/signals.py` (dual-path: single DynamoDB `system` item `key="signals"` or local `signals.json`), a bounded ring of the newest 200 events. The DynamoDB path appends atomically with `list_append` and trims with a size-conditioned `REMOVE` (bounded retries). `server.utils._server_log` writes to it alongside the logger and swallows persist errors, replacing a `server.log` file reader that nothing ever wrote to.
- Human-answer resume is idempotent across channels (dashboard/Slack/GitHub comment): the answer is recorded only after the resume job is enqueued, and a second answer is a no-op ack echoed into the Slack thread.
- Other design decisions from the previous snapshot (multi-part feature guard #38, shared failure escalation #42/#46/#47, human gate #55, closed-issue loop reconciliation, scheduler status single source) are unchanged by this diff.
