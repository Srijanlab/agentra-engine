- Dual-path storage: nearly every registry/memory write/read branches on `core._ddb is not None` (DynamoDB) vs. local JSON, with tests running the local path unless they explicitly stand up `moto`.
- Two independent credential surfaces for machine callers: `/internal/*` (shared `AGENTRA_INTERNAL_TOKEN` bearer + optional IP allowlist) for the loop, and per-route bespoke auth for triggers (`AGENTRA_TICK_TOKEN`/`CRON_SECRET` for cron, Basic auth for alarms, internal-bearer-or-Pub/Sub-OIDC for queue push, HMAC-compared `AGENTRA_VERIFY_TOKEN` for read-only black-box checks) — the Firebase gate in `auth.py` only ever covers the dashboard's own routes.
- Job/run liveness moved from a single fixed claim-age ceiling to an explicit heartbeat model: the loop renews a claimed job via `POST /internal/jobs/{id}/heartbeat` (`registry.touch_job`), and that same call refreshes the job's run's `updated_at` so `reconcile_stale_runs`/`reconcile_stale_loops` share one env-tunable threshold (`core.stale_heartbeat_seconds()`) instead of drifting independently.
- Scheduling is unified behind one pure computation (`registry.scheduler.compute_schedule_status`) consumed by both the cron enqueue path and the read-only `GET /apps/{app}/schedule` endpoint; adding `schedule_continuous` extended that same function/dataclass rather than forking a second due-ness code path.
- RPC surface area is an explicit whitelist (`_REGISTRY_METHODS`/`_MEMORY_METHODS`) plus a second explicit whitelist for cache-invalidating mutations (`_MEMORY_MUTATION_METHODS`) — additive by design, so a new capability requires two conscious edits rather than being auto-exposed.
- Payload/response Pydantic models for app config now live in a dedicated `routes/app_payloads.py` module rather than inline in the route file, keeping `routes/apps.py` under the file-size limit as fields like `schedule_continuous` are added.
