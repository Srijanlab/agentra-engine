Key design decisions and patterns actually in this codebase, as of this session's work (Codebase Agent overwrites this on its next real scan -- see agents/codebase.py's design_notes field):

- **Hybrid GitHub-authoritative config, local-fallback everywhere.** known_bugs/feature_queue (GitHub Issues, labels "bug"/"enhancement"), environments.yaml (GitHub Actions Variables, one per field), and objective.yaml (a single AGENTRA_OBJECTIVE variable) all follow the same pattern: try GitHub first, silently fall back to the local JSON/YAML mirror on any failure (not configured, unreachable, rate-limited). Every write also updates the local mirror regardless, so the system never becomes fully dependent on GitHub being reachable. See memory.py's known_bugs()/environments.py's load().

- **Deterministic git plumbing, never left to an LLM turn.** Branch checkout/commit (implementation.py) and merge/push (deployment.py) are done in plain Python, not as prose instructions to the agent. Confirmed live, twice, that an LLM given "checkout X, commit at the end" as prose does not reliably do either step.

- **Permanent-vs-transient failure triage, not a write-only audit log.** memory.py's record_failure()/is_transient_failure() replaced an earlier design (memory/{decisions,features,metrics,failures}/*.md, all write-only, confirmed nothing ever read them back) with an actual policy: a permanent failure (a real defect) becomes a GitHub Issue via record_known_bug, so Discovery Agent prioritizes fixing it; a transient one (rate limits, max-turns exhaustion, the Claude Code CLI's own contradictory-result quirk) is just logged, since a retry is the fix, not a backlog entry.

- **Two orchestration modes, one deterministic, one LLM-driven.** orchestrator.py's run_cycle() is a fixed pipeline (understand -> discover -> implement -> test -> deploy -> feedback, always in that order); agents/brain.py's run_autonomous_cycle() is the default, an LLM given the same steps as callable tools and free to sequence/retry them itself, with a stagnation breaker (OrchestratorSession) that detects no-progress loops and forces an early stop.

- **Self-hosting/dogfooding.** agentra manages its own repository as one of its own registered apps -- its own known_bugs, feature_queue, objective, and environments config live in this same repo, synced through the exact same code paths every other managed app uses. There is no special-cased "self" path anywhere.

- **Firestore is a durability mirror, never a requirement.** Run logs, signals, and the apps registry all write to Firestore *in addition to* local state when configured, and every read path falls back to local state if Firestore is absent or the write failed -- a cycle never blocks or crashes because Firestore is unreachable.

- **Steering files are live snapshots, not logs.** architecture/{codebase,design,testing-notes}.md are each overwritten fresh by their responsible agent every real run (Codebase Agent for the first two, Testing Agent for the third) -- they describe current truth, not history. architecture/documentation.md is the one exception: its top section is a static human-edited description, with a growing "## Changelog" section appended by whichever agent ships a feature (memory.py's append_documentation()).
