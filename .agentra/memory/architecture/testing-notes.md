Backend: a real pytest suite under tests/ (~150+ tests), covering server endpoints, Memory, the scheduler, agent chat/streaming, the standup channel, GitHub Issues backlog sync, and codebase-spec caching. Run with `pip install -e .[dev] && pytest tests`. Two tests are live-integration only and excluded from normal runs -- test_generic_spawn_integration.py and test_safety_integration.py -- they need real CLAUDE_CODE_OAUTH_TOKEN/ANTHROPIC_API_KEY credentials and cost real money; run them explicitly, never assume CI covers them.

Frontend: Vitest + React Testing Library exists on the `beta` branch (component tests for AgentsPanel, RunDetailDrawer, StandupsPanel) but has NOT been merged to `main` yet -- do not assume `npm test` exists when working on main until that lands. `npx tsc --noEmit` (typecheck) and `npm run build` (production build) work on both branches and are the minimum bar for any frontend change.

CI: a GitHub Actions workflow is defined at ci/github-actions-ci.yml (py_compile + pytest for the Python side, npm run build for the web side, triggered on push to main/beta and on PRs) -- but it is NOT actually installed under .github/workflows/, so it currently runs nowhere. The GitHub App's installation lacks the `workflows` permission scope needed to push directly into .github/workflows/ (confirmed live: an attempt was blocked). A human has to manually copy ci/github-actions-ci.yml into .github/workflows/ once for it to actually start running. It also doesn't yet have a step for the new Vitest suite -- only `npm run build`, no `npm test` -- so that would need adding too once installed.

For a normal code change today: `python3 -m py_compile <file>` + `pytest tests` (backend), `npx tsc --noEmit` + `npm run build` (+ `npm test` if working on beta) for the frontend, plus manually exercising the affected path (a local `agentra serve` run, or Playwright against it) -- that combination is the closest thing to a real test pass that actually happens right now, since nothing runs automatically on push.
