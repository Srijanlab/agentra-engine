# engine — Architecture

## Purpose
agentra-engine is the API + state-authority service of the agentra autonomous product-engineering platform. It owns all cross-app state (app registry, runs, loops, the job queue, per-repo memory) and every credential (GitHub App key, Slack bot token, DynamoDB/GCP auth), exposing them to the dashboard (agentra-ui) over an authenticated REST API and to the executor (agentra-loop) over a token-gated `/internal` RPC. It runs no LLM and no build/deploy work itself.

## Stack
- Python >=3.11 (Docker image python:3.12-slim); FastAPI + Uvicorn + Pydantic.
- Prod host: Vercel serverless — `api/index.py` is the ASGI entry, `vercel.json` rewrites every path to it, `requirements.txt` is the install (no uvicorn, no dev extras). `Dockerfile` is a fallback for plain container hosts. `sitecustomize.py` (repo root) forces the local `agentra/` package ahead of any installed copy on `sys.path` — auto-imported by the interpreter at startup.
- Persistence: DynamoDB via boto3 (static `AGENTRA_AWS_*` IAM keys) when `AGENTRA_DYNAMODB_TABLE_PREFIX` is set; otherwise local JSON under `AGENTRA_HOME` (default `~/.agentra`).
- Auth: Firebase/Google ID-token verification (`google-auth`) for the dashboard gate; `pyjwt[crypto]` for minting GitHub App installation tokens; a separate scoped read-only `AGENTRA_VERIFY_TOKEN` header for pre-prod black-box checks; bearer-or-Pub/Sub-OIDC for `/trigger/queue`.
- Observability: Langfuse (`langfuse>=4`), no-op without credentials.
- Tests: pytest + pytest-xdist (`-n auto` baked into `pyproject.toml`), `moto[dynamodb]`; `google-cloud-texttospeech` (dev extra) for `/tts`. CI (`.github/workflows/ci.yml`, push to main/beta + PRs): `pip install -e .[dev]`, `py_compile` every file, `pytest tests`.
- `agentra` console-script CLI (`agentra.cli:main`).

## Module map
- `agentra/server/` — the FastAPI app. `__init__.py` wires middleware + all routers; `auth.py` (Firebase sign-in gate, CORS regex, public-path list, delegates to `verify_token.py` first); `verify_token.py` (scoped `X-Agentra-Verify-Token` read-only gate for 3 GET routes, pre-prod only); `queue_auth.py` (internal-token-or-Pub/Sub-OIDC gate for `/trigger/queue`); `env.py` (unused `AGENTRA_PREFLIGHT_DEMO`/beta-prefix helpers — not imported anywhere); `routes/` (triggers, internal, apps, app_payloads (request-body models split out of apps.py), schedule, loops, systems, connectors, chat, standup, human_input, review); `state.py` (in-process `_active_runs`/`_app_locks`); `gh_cache/` (read-through TTL cache for the dashboard's GitHub-backed reads); `human_gate/` (raises a human gate for runs that end with a `HUMAN_INPUT_REQUIRED` note); `digests/` (awaiting-testing Slack digest); `utils.py`.
- `agentra/registry/` — multi-app registry + durable work queue. `core.py` (apps, pause, global + per-app-per-SDLC-agent LLM backend, `RepoSpec` resolution, DynamoDB init, Slack-thread map, `stale_heartbeat_seconds()`), `jobs.py` (`cycle|promote|prod_debug|human_resume` queue the loop drains; per-app claimed-job lease with heartbeat renewal (`touch_job`) and `release_job` for graceful shutdown; poison-job terminal-fail after `max_job_attempts()`), `runs.py`, `loops.py`, `inbox.py`, `scheduler/status.py` (read-only `compute_schedule_status` — fixed-cadence or continuous-run due timing), `_dynamo.py`, `_cache.py`. The module object is replaced by a proxy that delegates `_DELEGATED_NAMES` to `core`.
- `agentra/memory/` — per-repo product state. `Memory` = 5 mixins (issues, issue_lifecycle, features, settings, specs); GitHub Issues/Projects-backed. `core.py` holds label constants (incl. the `status:awaiting-testing` label and its legacy `status:shipped` alias) + failure-triage regexes + spec-header helpers + `pipeline_stages()`.
- `agentra/connectors/` — GitHub App (`github_app.py` mints a per-`owner/repo` installation token), issues/pulls/projects/variables/issue-lifecycle mutations (incl. `migrate_awaiting_testing_label`; `open_sub_issue_count` via GraphQL), `github_fake.py`, Slack (`slack.py` + `slack_allowlist.py`).
- `agentra/a2a/` — read-only A2A agent-discovery cards + `/.well-known/agent-card.json` (`routes.py`); task/message/part models aren't wired to executable dispatch here.
- `agentra/agents/` — `catalog.py` only: static per-agent capability/tool metadata for `/agents/metadata` and the a2a cards. No executable agents.
- `agentra/proxy/` — standalone FastAPI app translating the Anthropic Messages API to NVIDIA NIM chat-completions (the `nim` LLM backend).
- `agentra/` root — `cli.py`, `environments.py` (per-app pipeline config, incl. `schedule_continuous`, stored in GitHub Actions Variables), `git_ops.py` (push/clone/commit, with a targeted GitHub-App-`workflows`-permission hint on push failure), `artifacts.py`, `change_risk.py`, `ranking.py`, `chat_store.py`, `urls.py`, `langfuse_api.py`, `observability.py`, `dev_seed.py`.
- `api/index.py` — Vercel entrypoint; serves a diagnostic fallback app if `agentra.server` import fails.
- `tests/` — pytest suite; `conftest.py` strips prod-pointing env vars at import.

## Invariants
- The engine never executes a cycle / promotion / prod-debug / resume. Trigger endpoints call `registry.enqueue_job(...)`; agentra-loop claims and runs it. No `claude-agent-sdk` dependency.
- The loop reaches engine state only through `POST /internal/rpc` (bearer `AGENTRA_INTERNAL_TOKEN`), restricted to the `_REGISTRY_METHODS` / `_MEMORY_METHODS` frozenset whitelists; it never touches DynamoDB or GitHub directly. The GitHub App key and `SLACK_BOT_TOKEN` stay in the engine — the loop calls `/internal/git-token` and `/internal/slack/message`.
- Exactly one repo per app has `role="coordination"` (issues, `.agentra/memory`, objective); `Memory` is always the coordination repo. A legacy single-repo app has one `RepoSpec` that is both coordination and code.
- `cloud_mode()` (== DynamoDB configured) means no writable checkout: local-file `Memory` methods and `persist_agentra_dir` become no-ops / raise `OSError`, and repo resolution returns the stored path unresolved.
- `AGENTRA_AWS_*` is deliberately prefixed, not bare `AWS_*` — Vercel's Lambda runtime reserves the bare names for its own execution-role creds.
- A job claim is a CAS `pending -> claimed` on the `by-status` GSI, and holds a per-app heartbeat lease: `_requeue_stale_claims` re-queues any claimed job whose *app's* most recent heartbeat exceeds `stale_heartbeat_seconds()` (default 1h, `AGENTRA_STALE_HEARTBEAT_SECONDS`), so a crashed loop can't strand work; `touch_job` (called from `POST /internal/jobs/{job_id}/heartbeat`) renews the lease and bumps the tied run's `updated_at`. A job that exhausts `max_job_attempts()` (default 3) goes terminal-failed with a `HUMAN_INPUT_REQUIRED` error and a poison-job Slack notify, instead of being re-queued forever. `release_job` (CAS-guarded on `claimed_at`) lets a shutting-down loop container hand its job back to `pending` immediately, without touching its attempt count. Terminal jobs carry `expires_at` for DynamoDB native TTL.
- `/health` and `/healthz` are identical and must never fail on a backend blip (catch-all -> `{status: degraded}`). Both also return `commit` (deployed `VERCEL_GIT_COMMIT_SHA`, fallback `AGENTRA_BUILD_SHA`, else `""`) so the loop's `verify_pre_prod` can confirm a pre-prod deploy has caught up.
- The pre-prod-merged-awaiting-verification status label was renamed `status:shipped` -> `status:awaiting-testing` (GitHub issue #38); every write path emits the new name and strips the old, but every read path still matches both.
- A loop left `active`/`waiting_for_human`/`escalated` whose tracked issue is later closed by a human is otherwise orphaned forever: `_reconcile_closed_issue_loops` (run for every app on each `/trigger/cron` tick) marks it `released` with pipeline `terminal=True` (agentra#20/#25).
- A terminal run whose `error` or `summary` contains `HUMAN_INPUT_REQUIRED` must never end silently (#55): `human_gate.maybe_raise(run_key)` runs after every successful `record_run` RPC, and `sweep_recent_runs()` retries recent runs on each `/trigger/cron` tick.
- A parent issue with open sub-issues is never marked code-complete: `Memory.record_code_complete` checks `github_issues.open_sub_issue_count` and returns `blocked_by_open_sub_issues` (#38).
- `find_unanswered_human_input_comment` accepts only comments after the MOST RECENT human-input marker (agentra#54).
- `record_failure` dedups on `_find_similar_open_bug` for both auth and unfixable failures (#47); a first-time unfixable non-auth failure is escalated via `_escalate_blocking_failure`, same as auth failures.
- `POST /trigger/queue` is fail-closed 401 unless the bearer is `AGENTRA_INTERNAL_TOKEN` or a Google-signed Pub/Sub OIDC token whose audience matches `AGENTRA_PUBSUB_AUDIENCE` (and whose verified `email` matches `AGENTRA_PUBSUB_SERVICE_ACCOUNT_EMAIL` when that's set); with neither configured, every request is rejected.
- `GET /trigger/cron` accepts `AGENTRA_TICK_TOKEN` or `CRON_SECRET`; `AGENTRA_INTERNAL_TOKEN` is honored only as a fallback while `AGENTRA_TICK_TOKEN` is unset (issue #80), and it fails closed once any credential or DynamoDB is configured.
- `AGENTRA_VERIFY_TOKEN` (`X-Agentra-Verify-Token`, constant-time compared) authorizes only `GET /apps`, `GET /apps/{name}/schedule`, `GET /runs/{run_key}` — every other route/method 401s even with a correct token, and Production (`VERCEL_ENV`/`AGENTRA_ENVIRONMENT` == `production`) always returns 403 for the header regardless of validity. It never authorizes `/trigger/cron` or `/internal/*`.
- Per-app LLM backend is keyed by SDLC agent id (`VALID_SDLC_AGENT_IDS`), not one flat value: `get_app_llm_backend(name, agent_id="implementation")` reads `get_app_llm_backends(name)`, which merges the stored `llm_backends` map over a `"claude"` default per agent and folds in the legacy single `llm_backend` field as `"implementation"`'s value — a write must go through `set_app_llm_backends`/`set_app_llm_backend` (validated against `VALID_APP_LLM_BACKENDS`) so both shapes stay merged.
- `schedule_continuous=True` overrides `schedule_hours` for due-timing: `compute_schedule_status` runs `_continuous_due` instead of the cadence-hours formula — an app is due `continuous_gap_seconds()` (default 60s, `AGENTRA_CONTINUOUS_GAP_SECONDS`) after its last cycle-run activity, or never while a cycle job/run is in flight (`cycle_in_flight`); `schedule_enabled` is true whenever either `cadence_hours > 0` or `schedule_continuous`.

## Conventions
- Every registry/memory storage function branches `if core._ddb is not None: <dynamo> else: <local JSON>`; new state follows the same dual-path shape with a local fallback for tests/dev.
- `registry` sub-modules re-export through `registry/__init__.py`'s `__all__`; when adding one, update the `routes/internal.py` `_REGISTRY_METHODS`/`_MEMORY_METHODS` whitelist in the same change if the loop needs it.
- A new whitelisted `_MEMORY_METHODS` entry that mutates GitHub Issues/Projects state must also go in `_MEMORY_MUTATION_METHODS` (`routes/internal.py`), or the app's `gh_cache` entries aren't invalidated after the RPC.
- Dashboard GitHub-backed read endpoints go through `gh_cache.cached(key, producer)`; a new per-app cache key must be added to `gh_cache.invalidate_app`.
- Routes are `APIRouter`s included at root prefix in `server/__init__.py`; auth exemptions go in `auth.py::_PUBLIC_PREFIXES`; a new scoped bearer/token gate (queue, tick, verify) gets its own small module (`queue_auth.py`, `verify_token.py`), not inline logic in `auth.py`.
- Work-enqueuing endpoints: check `registry.is_paused()` first, dedup with `dedup_key=f"{kind}:{app}"`, record a run via `_new_run_key`, return `{triggered, run_key, job_id, queued}`.
- Schedule-due timing lives in one place: `registry.scheduler.compute_schedule_status(app, repo)` is shared by the `/trigger/scheduled` cron enqueue path and the read-only `GET /apps/{app}/schedule`; don't re-derive `due_in` from `environments.load` + `last_run_at` inline.
- Pipeline stage ordering/display lives in one place too: `memory.core.pipeline_stages()`, served read-only via `GET /pipeline/stages`.
- Request/response payload models for a route module live in a sibling `_payloads.py` (e.g. `routes/app_payloads.py`), not inline in the route file, per the per-file 500-line limit + SRP + subfolder-per-domain rule (`CLAUDE.md`): split into mixins/packages rather than growing a file. Single-sentence docstrings, no dead code, no comment paragraphs.
- A feature that needs a repo checkout or Claude is held with HTTP 503 and a "moving to agentra-loop" message, not partially implemented (`chat.py`, `standup.py`).
- `_json_safe` coerces dataclasses/`Path` for anything returned over RPC.
- Any orchestrator-authored comment posted on a GitHub issue must have its prefix added to `_INTERNAL_COMMENT_PREFIXES` (`connectors/github_issue_lifecycle.py`) in the same change.
- Escalating a blocking failure to a human goes through `MemoryIssuesMixin._escalate_blocking_failure`, not a bare Slack post.
- A job/run heartbeat renewal (loop keep-alive) is a small, separate `/internal/jobs/{job_id}/heartbeat` endpoint, not folded into the general `/internal/rpc` whitelist dispatch.

## Gotchas
- `tests/conftest.py` pops `AGENTRA_ENGINE_URL`, `AGENTRA_DYNAMODB_TABLE_PREFIX`, `AGENTRA_AWS_*`, and GCP vars before anything imports `agentra` — running pytest with those set has previously written test fixtures straight into prod.
- `registry` and `memory` are import-time module swaps/proxies. `import agentra.registry as r; r._ddb = x` writes through to `core`, but only for names in `_DELEGATED_NAMES`.
- `/internal/rpc` ignores `x-forwarded-for` on purpose (client-spoofable); only Vercel-set `x-real-ip` / `x-vercel-forwarded-for` are trusted for the IP allowlist.
- `_memory_for` over RPC returns a real `Memory` only if the coordination-repo checkout happens to exist on the engine host; otherwise a `_UrlMemory` on a throwaway tmpdir whose local-file methods write nowhere useful.
- No inbound Slack/GitHub webhook: human answers to `need_human` issues are discovered by polling issue comments on the `/trigger/cron` tick.
- Off cloud mode, `get_app_repo` runs on nearly every request and may `git pull` (throttled to once per 30s per repo) — a slow remote slows the whole API.
- DynamoDB init never raises: on bad creds `_ddb` is `None` and the engine silently falls back to local JSON (empty in prod). Diagnose via `/debug/dynamodb`.
- `agents/catalog.py` still describes the full agent pipeline that actually runs in agentra-loop — display metadata only.
- Vercel function `maxDuration` is 30s; any endpoint doing real work must enqueue a job, not block.
- Label membership against a live GitHub issue must go through `_label_names()` — `github_issues.get_issue` returns real REST label objects (`{name: ...}`), not flat strings; only `github_fake` uses flat strings.
- `list_loops` sorts by `_recency()` (last_run_at) not `updated_at`; the DynamoDB `by-app-recency` GSI is keyed on `updated_at`, so `_query_loops_by_app` overfetches (`_RECENCY_OVERFETCH`=200) and re-sorts in Python.
- `gh_cache.cached` is stale-on-error: if the producer raises and any prior entry exists, that value is served regardless of age; a mutating RPC missing from `_MEMORY_MUTATION_METHODS` leaves the dashboard stale until TTL.
- `human_gate` matches the bare `HUMAN_INPUT_REQUIRED` substring in a run's `error` OR `summary`, and only announces once a Slack thread is recorded.
- `server/env.py` (`AGENTRA_PREFLIGHT_DEMO`/`get_dynamo_table_prefix`/`get_internal_token`) is dead code — nothing in the app imports it; `core._init_dynamodb`/`routes/internal.py::_require_token` read `AGENTRA_DYNAMODB_TABLE_PREFIX`/`AGENTRA_INTERNAL_TOKEN` directly, so setting only the `BETA_*` variants this module expects silently does nothing.
- `sitecustomize.py`'s `sys.path` rewrite matches on the literal substrings `'editable'`/`'agentra-0.1.0'` in existing path entries to decide where to insert the repo root — a renamed venv or package version can make it insert in the wrong place (or not at all) and a stale installed `agentra` shadow the local checkout.
- `push_branch`'s GitHub-App-`workflows`-permission special case matches on raw stderr text (`'refusing to allow a GitHub App to'` + `'workflows'` + `'permission'`); a GitHub-side wording change silently falls through to the generic error instead of the actionable hint.
- `_verify_tick_auth` still accepts `AGENTRA_INTERNAL_TOKEN` for `/trigger/cron` whenever `AGENTRA_TICK_TOKEN` is unset — provisioning a dedicated tick token is the only thing that closes an RPC-token holder's ability to trigger scheduler ticks (issue #80).
- A `schedule_continuous` app is never "next due" in the normal sense (`next_scheduled_run_at` is `None` while in flight); dashboards reading `next_scheduled_run_at` as a fixed future timestamp will see it flicker to `None` every time a cycle is running.
